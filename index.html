Project objective

  • Generate the synthetic demand dataset with a fixed seed.
  • Keep the split chronological: train days 1–120, validation 121–150, test 151–180.
  • Use only information genuinely available before the day starts.
  • Report a naive baseline before any modelling.
  • Leave the test set untouched until the final evaluation.
Problem
Forecast bike demand without time leakage.
Target
Daily demand for a fictional bike-rental service.
Metric
Mean absolute error (MAE).
Risk
Using same-day features creates an impossible model.

Exploratory analysis

Feature and leakage decisions

Column Known before day starts? Notes
day Yes Sequential time index used for the split and trend.
weekday Yes Strong weekly effect in the synthetic demand pattern.
temp No Same-day temperature is not known before the day begins.
rain No Same-day rain is not available at prediction time.
demand No This is the target variable to predict.
The most important rule in this project is not to let future information leak into a prediction. Same-day temperature and rain were intentionally excluded from the model, even though they are present in the data.
The candidate model uses weekday, seasonal terms, and lagged demand/rain values that are feasible at prediction time.

Final interpretation

The honest outcome is that the previous-day baseline is a strong benchmark, and a simple linear model using only pre-day information improves materially on it. This is a meaningful validation result because it follows the rules of the project: no random split, no same-day feature leakage, and no early spending of the test set.
