Project objective

  • Generate the synthetic dataset with a fixed seed.
  • Split chronologically: train = days 1–120, validation = 121–150, test = 151–180.
  • Use only information known before the day starts.
  • Report a naive baseline before any modelling.
  • Leave the test set untouched until the final evaluation.
The biggest risk here is leakage. Same-day temperature and same-day rain are in the data but are not available at prediction time, and using them would make the model look better than it really is.

Final takeaway

The honest result is that the simple linear model beats the naive forecast on validation and does so without violating the project rules. The interpretation is therefore valid: this is a better model than the baseline for the validation period. The unseen test period remains untouched and should be used only once at the very end.
